# P0 acceptance: what counts as "since I read it"

The plan's first failing acceptance, captured as evidence and pinned as
regressions. Everything here runs the real export path (build_edition →
`gaceta agent export` → `gaceta agent since`) on the synthetic
since-world fixture; nothing touches real data, credentials or networks.

## The recorded failure (why P0 exists)

In the pre-P0 combined evaluation, a configured client with a correct
JSON status in hand still wrote a wrong free-form answer: it inferred a
reading date from a version ("you last read the D1 edition") and called
the intervening edition "skipped". A correct `baseline.status` alone did
not prevent it — the payload itself licensed the claim. (Recorded in
`docs/DISCOVERY-AND-TRIAL-PLAN.md`, "Starting evidence".)

## The red captures (frozen)

The three `red-*.json` files are **real CLI output of the pre-change
candidate**, captured 2026-11-19 before any P0 edit (pre-change
`src/gaceta/agent.py` sha256
`4903b6ff97cb1914d60b5c246a75fb2bbad6af77a21b9a3a21322d4fc2804bca`).
They cannot be regenerated by the current code — that is the point of
red. What in them licenses the failure:

- `red-version-only.json` — baseline states only `stOld:1`. The JSON
  statuses are correct, but the chronology block is named
  `skipped_editions`, the semantics say "your last-read edition date" as
  if one were stated, and the full public build trace (D1/D2/D3) rides
  along next to v1's trace stamps. A model reading this synthesized a
  reading date and a skipped edition from a version.
- `red-cycling-interest-no-last-read.json` — the reader follows the
  story but has no record for it. The brief says a bare "unknown" and
  never cites the correction: an interested reader is told nothing the
  paper actually has on record, so the answer either invents or goes
  empty. The public fact (the correction) and the personal unknown
  ("new to you") are not separable because the citation is not there.
- `red-dates-and-versions.json` — with a stated date, the note reads
  "public editions built after your baseline date with no baseline
  record of reading them": the field name and note assert non-reading
  from chronology, which is exactly the claim P0 forbids.

## The green contract (pinned)

The passing behavior is pinned by
`tests/test_p0_baseline_contract.py` (schema) and by the wording rules +
two exemplar answers in `docs/agent/SKILL.md` (free-form shape):

1. **Version-only** — the correction is cited with its public source,
   and the answer claims no reading date, no skipped edition, and
   nothing about delivery or access cycles. `intervening_editions` is
   explicitly unknown; nothing derives a date from a version.
2. **Cycling interest, no last read** — the paper's latest correction is
   cited as a public fact (`change.on_record`), stated *separately* from
   "whether any of it is new to you is unknown". Neither "nothing new"
   nor "new to you".
3. **Dates** — a stated date bounds publication chronology only.
   `intervening_editions` lists the public editions BUILT between the
   stated date and the current one, with a note that it is not evidence
   of skipping and says nothing about delivery or access.
4. **Provenance** — every stated baseline fact carries its origin as the
   caller states it (`user_statement`, `verified_receipt`, `unknown`).
   A label is never authentication: a self-labeled `verified_receipt`
   grades identically to `user_statement`, and the receipt path's real
   output is still evidence-checked like any claim.

## API stability (brief v2)

The rename is not silent: the brief carries `brief_version: 2`, and the
old `skipped_editions` key is **retained, deprecated, and always null**
— legacy clients never meet a disappeared field, and the old name can
never again deliver a claim-shaped list. `semantics.brief_version` says
so in the payload itself.

## Limits

- The JSON side and the taught wording are pinned here. Live free-form
  model turns (both acceptance scenarios rendered by a real configured
  client) are P5 cleanroom work; this file makes the schema and the
  skill unable to license the failure, not the model unable to fail.
- Red captures are of the synthetic fixture world only.
