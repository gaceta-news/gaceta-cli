# P4 packaging — distributable surfaces, one source of truth

Scope (from the plan's P4): canonical public page in EN and ES, portable
skill packages for the two candidate clients on their **stock supported
paths**, listing drafts, version/metadata parity with a CI gate, and
packaged demo installation tests. No publishing, no registry or hub
submissions, no maintainer contact, no edits to live tool profiles, no
promotional installs. Everything here is candidate evidence, not a
compatibility claim.

## Layout

```
packaging/
  catalog.json          ONE metadata source: names, descriptions, links,
                        tags, tested_with (read by every artifact below)
  templates/            the shape of each artifact ({{PLACEHOLDER}}s only;
                        the skill body is NOT templated — it is injected
                        from docs/agent/SKILL.md at build time)
  dist/                 generated by scripts/build-packages.py — review,
                        commit, ship; CI rejects any drift
    hermes-skill/research/gaceta/     → unzip into ~/.hermes/skills/
    codex-skill/gaceta/               → unzip into $HOME/.agents/skills/
    codex-plugin/                     → Agent Plugins package (plugin.json)
    codex-marketplace/                → `codex plugin marketplace add` root
                                       (manifest at .agents/plugins/marketplace.json)
    web/landing.en.md + landing.es.md → the canonical public page, drafted
    listings/hermes-hub.md + codex-plugin.md → catalog listing DRAFTS
    archives/*.zip                    → version-pinned companion downloads
    MANIFEST.json                     → every file + sha256 (no clocks)
```

Version: **0.3.0b1**, the intended beta candidate. It lives only in
`src/gaceta/__init__.py` (`__version__`); `pyproject.toml` reads it
dynamically, the wheel records it, `gaceta --version` prints it, and every
packaged artifact is stamped from it. Why a beta: the published 0.2.x tags
(v0.2.0 … v0.2.2) predate the agent-demo wheel assets, `--version` and
these packages — pinning a public install at 0.2.0 would point readers at
a gaceta **without** the advertised features. `v0.3.0b1` is cut at release
review; until then the landing's install command is the shape of the pin,
not a live URL, and says so.

## Commands

```bash
python scripts/build-packages.py        # (re)render packaging/dist
python scripts/check-parity.py          # the gate: run by make check + CI
bash scripts/test-packaged-install.sh   # clean wheel, packaged demo, stock
                                        # client round trip (sandboxed)
make check                              # suite + parity
make packages                           # shorthand for the build
```

## What is actually tested (real outputs, 2026-11-19)

- `scripts/test-packaged-install.sh` — end to end, exit 0:
  locked export → `gaceta-0.3.0b1-py3-none-any.whl` → fresh venv
  (CPython 3.12.12) → `gaceta --version` → **0.3.0b1**, wheel METADATA →
  **0.3.0b1**; wheel ships `gaceta/assets/agent_demo/make_demo_export.py`
  and **no** pre-built `export.json`; the packaged skill's demo (dist files,
  outside the checkout) runs the three read-only commands — 3 stories,
  `demo-aurora` 2 sources + 1 correction, version-only baseline →
  `known` → `material_change` with 2 supporting sources, `demo-aurora`
  `unknown`, honest skipped-editions note; all 3 archives byte-identical to
  dist.
- **Codex, stock only, no adapters:** `codex plugin marketplace add
  packaging/dist/codex-marketplace` → `Added marketplace gaceta-news`;
  `codex plugin add gaceta@gaceta-news` → `Added plugin gaceta`;
  `codex plugin list` → `gaceta@gaceta-news installed, enabled 0.3.0b1`;
  the skill lands at `$CODEX_HOME/plugins/cache/gaceta-news/gaceta/0.3.0b1/
  skills/gaceta/SKILL.md`; remove plugin + marketplace clean. Run against a
  sandboxed `CODEX_HOME` — the real `~/.codex/config.toml` was untouched
  (mtime verified). No experimental feature flags, no legacy
  `~/.codex/skills` v1 location, no broker/adapter. Discovered against
  codex-cli 0.171.0: the marketplace manifest must sit at
  `<root>/.agents/plugins/marketplace.json` — the docs' repo-scoped
  convention.
- **Hermes, honestly not exercised:** `hermes skills install/inspect`
  accepts registry refs or HTTPS URLs to a public `SKILL.md`, not local
  paths (verified: `hermes skills inspect <local dir>` → "Could not find …
  in any source"), so the stock install path needs the pinned public
  release source. Validated instead: frontmatter/layout per the stock
  skills conventions (name/description/version/author/license/platforms;
  60-char description hardline) — enforced by `scripts/check-parity.py`
  and `tests/test_packaging.py` — plus the demo through the installed
  wheel. No adapter fakes a configured-client run; that is P5 cleanroom
  evidence with its own pre-registered matrix.
- `python scripts/check-parity.py` — PARITY OK (all checks listed in the
  script header), including: rendered `SKILL.md` bodies contain the
  **current** `docs/agent/SKILL.md` body (build-time injection, so the
  P0-tested read-only discipline can never rot into a stale template copy).

## Not claimed

Blind discovery, catalog indexing, configured usage, reader retention,
cold GitHub install, and the Hermes hub/registry round trip are **not**
exercised or claimed. Catalog acceptance and indexing are external
dependencies, not CI assumptions. The live Hermes profile already carries
an unrelated `gaceta-reader-sou…` skill from another workstream; it was
left untouched (read-only inspection only).

## Overlaps with other work packages (scope preserved)

  discipline text and the single body source for the packaged skills;
  `docs/agent/demo/make_demo_export.py` stays the canonical demo generator
  (its wheel copy under `src/gaceta/assets/agent_demo/` is CI-verified

  pinned at release" note and does not assume its contents.
- **P2 recipe / P3 trial:** commands are not in this candidate; the
  landing marks both as parallel candidates to be linked once merged, with
  their boundaries (share-nothing default; three-edition, non-renewing
  trials) already stated.
- **Release checklist (`docs/release/pilot.md`):** unchanged; this package
  adds the parity gate and packaged-install test it presumes.
